# com_servicedeskplus 1.20.1

Security and clean-up release after a review of the whole component. Update from **System → Update → Extensions**, or install `com_servicedeskplus.zip` (attached below). No database changes. **Updating is recommended.**

## Security fixes
- **No automatic matching after an e-mail change.** Until now, a user who was not yet matched could change their Joomla e-mail to someone else's address and be matched to that person's ServiceDesk Plus account. Now any changed e-mail suspends the mapping until an administrator checks it under *User Mappings*.
- **Several ServiceDesk Plus users with the same e-mail** are no longer matched automatically: an administrator chooses.
- **The API key must be entered again** when you change the ServiceDesk Plus address, *Connect via*, the certificate pin or CA file, or turn off the certificate check, so the stored key cannot be sent to another server.
- **Page permissions could be skipped** with a crafted link (only the user's own data was visible). This is now refused.
- **Pinned certificates** fail safe on servers whose cURL cannot check a pin.
- **One decision per approval level at a time** (double clicks, two tabs, two approvers).

## Other fixes
- A ServiceDesk Plus outage no longer keeps My Approvals and the Dashboard loading for minutes.
- After a failed decision you stay on the approval; an expired page says so.
- Rejected form values no longer stay in Integration Settings and the mapping form.
- The CA bundle field accepts Windows paths and paths with spaces.

## What you may notice
- Users whose Joomla e-mail changed appear as *Suspended* under *User Mappings*. Check that the new e-mail belongs to the person, then use *Match again* (or map them with *New*).
- When you change connection settings, Integration Settings asks for the API key again.
- If your site allows self-registration, keep *Users → Options → New User Account Activation* on **Self** or **Administrator**.
